        } else {
          // 0.78-1.00: message 5 fully visible hold.
          gsap.set(proofLayers[4], { opacity: 1, scale: 1 });
        }
        return;
      }

      let activeIndex = stageStarts.length - 1;
      for (let i = 0; i < stageStarts.length; i += 1) {
        if (p >= stageStarts[i]) activeIndex = i;

================================================
9. WHY THE 5TH POINT RELEASES EARLY
================================================

Primary cause lines in current code:

1) The 5th message enters only in a late progress window:
   const finalFadeStart = 0.64;
   const finalFadeEnd = 0.78;

2) Hard reset loop on every onUpdate tick:
   for (let i = 0; i < totalSteps; i += 1) {
     gsap.set(proofLayers[i], { opacity: 0, scale: 1.02, pointerEvents: "none" });
   }

3) Wrapper has fixed desktop height while pin end is separately computed:
   md:h-[240vh]
   and
   end: () => `+=${Math.round(window.innerHeight * 2.8)}`

4) Additional boundary overlap logic executes for earlier stage bands:
   const nextBoundary = stageStarts[activeIndex + 1];
   if (typeof nextBoundary === "number" && p >= nextBoundary - overlapHalf && p <= nextBoundary + overlapHalf) { ... }

Why this can look early:
- message 5 starts only at 0.64 progress and reaches full at 0.78.
- if scroll traverses quickly/scrub interpolation is coarse, time at fully settled state can feel short.
- repeated per-tick gsap.set resets can make the final state feel unstable right before release.
